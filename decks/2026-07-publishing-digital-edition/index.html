01

What does it mean to publish a digital edition?

  • "public" is the word doing the work in "publication"

The XML is not the edition

An edition sitting in a repo is not published.

published = viewable findable citable durable
  • Sahle: a digitized edition is not a digital edition — if you can print it without loss, it was never digital. the edition = text + encoding + presentation + access, not the file
  • jTEI 2016 (Turska/Cummings/Rahtz): interfaces rot, the source is the scholarship
  • so: source = scholarship, publication = a separate, deliberate act on top

Published means…

  • viewable — a human can read it, not just a parser
  • findable — metadata and a place where people discover it
  • citable — a stable, versioned reference to point at
  • durable — it outlives the server, the grant, the laptop
  • display → viewable; metadata + DOI → findable, citable; archiving → durable
  • print bundled all four invisibly; the web unbundles them

The yardstick: FAIR

GO FAIR principles
Wilkinson et al. 2016, Scientific Data

F

Findable

rich metadata and a persistent identifier

→ today: a DOI

A

Accessible

retrievable by humans and machines

→ today: open hosting

I

Interoperable

standard formats others can parse

✓ all week: TEI-XML

R

Reusable

clear licence, provenance, versions

→ today: licence + release

  • born: Lorentz Center Leiden, 27-31 Jan 2014, workshop "Jointly Designing a Data FAIRport", ~30 people — life scientists tired of data sharing = "email the corresponding author and pray"
  • paper: Scientific Data, March 2016 — among the most-cited papers of the decade
  • G20 communiqué + EU Horizon picked it up within months — why every EU grant asks about it
  • FAIR is not open: "as open as possible, as closed as necessary" — data may be closed, the metadata must be open; a rights-encumbered edition can still be FAIR
  • I is already done (a week of TEI); today adds F, A, R: DOI, hosting, license, release

From TEI to something human-readable

  • you have TEI — who can actually read it?

The spectrum

browse editions:
Catalog of Digital Scholarly Editions · Catalogue of Digital Editions

The TEI file is the website: a small JavaScript library teaches the browser to display TEI tags directly, styled with plain CSS. One source, no transformation pipeline — and anything beyond display is yours to build.

Frankenstein Variorum · CETEIcean live examples

Transform once, serve forever: a generator bakes the TEI into plain HTML pages that any host can serve — GitHub Pages, for free. No moving parts after the build: nothing very little to patch, and nothing very little left to break.

DIY-frankensTEIn · Endings-compliant editions (UVic) · minimal computing

Edition-shaped software: ready-made reading environments — facsimile beside transcription, edition levels, critical apparatus, witness comparison. You configure instead of program, and the result is still just files on a web server.

Codice Pelavicino (EVT) · Versioning Machine samples · LERA demos

The edition as an application: an XML database answers readers’ queries live: full-text search, filtering, views on demand, etc. The most powerful end of the axis. Somebody must run, patch and migrate the server.

edition humboldt digital · TEI Publisher registry · TEI Publisher demos

  • the axis is really a maintenance promise: client-side = nothing but a browser; server = a person, forever
  • minimal computing: GO::DH, ~2014-15 — no server, no budget, unreliable electricity; came out of working with colleagues in Cuba. Wax comes from that movement
  • Endings Project (UVic, ~2016): what kills editions is dependency, not disk failure — the PHP upgrade, the departed developer
  • CETEIcean = "cetacean": TEI elements become HTML custom elements, zero transformation
  • EVT: Pisa, built for the Vercelli Book. Versioning Machine: ~2000, the veteran. LERA: Halle, long prose versions
  • TEI Publisher: e-editiones society (2020); flagship edition-humboldt.de
  • Edition Light = the static-sites card

03

Whose edition is it?

  • readable — but whose is it? rights in: text, images, process; rights out: your rights, your license

Rights in, rights out

  • the text — copyright runs until 70 years after the author’s death. Your medieval scribe is safe; modern and born-digital authors usually are not.
  • the images — in the EU, a faithful scan of a public-domain work is itself public domain (DSM art. 14). But your contract with the holding institution can still restrict use.
  • the process — keystroke logs of a living writer are personal data under EU law: you need consent, not just copyright.
  • your copyright is thin — a faithful transcription adds no original creation, so it earns little or no copyright of its own.
  • …but some countries step in — Germany gives the editor a 25-year exclusive right in the edited text (§ 70 UrhG): others may not simply republish it.
  • declare it — a LICENSE file in the repo, <licence> in the teiHeader. Undeclared = all rights reserved.
  • life + 70: Conan Doyle (d. 1930) safe; a 1990s notebook is not — permissions-land is why editions cluster pre-1900
  • images: US Bridgeman v. Corel 1999 — faithful repro = no copyright (Feist 1991 killed "sweat of the brow"). Germany: Reiss Engelhorn Museum sued Wikimedia 2015 over 17 photos, BGH agreed 2018 — then DSM art. 14 (2019) overruled it EU-wide: won the battle, lost the war
  • contracts still bite: archive terms of use don't care about art. 14
  • thin copyright: the better the transcription, the less protected — fidelity is the opposite of originality
  • § 70: scholarly edition, 25 years. § 71 editio princeps: first publication of a never-printed work = 25 years exclusive — a first edition of an unpublished medieval text is not as free as you'd think
  • keystroke logs of a living writer = personal data (pauses, deletions, 2 a.m. revisions) → consent, not just copyright

Pick a license

CC license chooser
choosealicense.com

the edition — text, encoding, images

  • CC BY reuse with attribution — the scholarly default
  • CC BY-SA …and derivatives must share alike
  • CC0 no conditions at all — the norm for metadata
  • NC ND avoid: they block teaching, anthologies, derivatives

the code — XSLT, scripts

  • MIT do anything, keep the notice — short and permissive
  • GPL-3.0 derivatives must stay open (copyleft)
  • CC not for code — Creative Commons says so itself

No license = all rights reserved — reuse is legally blocked, and the R of FAIR fails.

  • 1998 Sonny Bono Act ("Mickey Mouse Protection Act") → Eldred v. Ashcroft lost 2003 → Creative Commons founded 2001, first licenses Dec 2002 — billions of works now
  • CC BY = do anything, attribute. edition humboldt digital: CC BY-SA
  • CC0 (2009): attribution is friction at scale — nobody can attribute fifty million metadata records; Europeana norm
  • NC is undefined: paid summer school? press anthology? reusers walk away. ND forbids what scholarship is
  • CC themselves say: not for code (no patent grant) → MIT or GPL
  • no license = all rights reserved, automatically (Berne) — public on GitHub grants nothing

04

Citable & durable: Zenodo + GitHub

  • readable, licensed — now citable and durable; the hands-on cashes this out

Hosting ≠ preservation

GitHub Pages is a website. A website is not an archive.

  • links rot — roughly one in five scholarly articles suffers reference rot; half the web links in U.S. Supreme Court opinions are dead (hence Perma.cc)
  • platforms die — GeoCities, Google Code, Bitbucket’s Mercurial repos: all gone. GitHub is a company, not a memory institution
  • preservation is a promise — an institution’s commitment, redundant storage, and a persistent identifier. Not a feature you toggle
  • Klein et al. 2014 (PLOS ONE): 1 in 5 articles suffers reference rot
  • Zittrain/Albert/Lessig 2014: 50% of Supreme Court links dead, 70%+ in Harvard Law Review → Perma.cc
  • GeoCities: founded 1994, Yahoo paid ~$3.6 billion in 1999, deleted it 26/27 Oct 2009; volunteer rescue ≈ 1 TB torrent
  • Google Code closed 2016; Bitbucket deleted every Mercurial repo 2020
  • GitHub is a company, not a memory institution — companies have exits, institutions have mandates
  • ask: what survives your GitHub account, your funding, your career?

The archive layer

Zenodo

the deposit

  • CERN-run — stored in the CERN Data Centre; retained for the lifetime of the lab
  • free — up to 50 GB per record; the DOI registers within seconds
  • GitHub-aware — one switch: every release archived, each with its own version DOI

belts and braces

free extras

  • Software Heritage — already archives every public GitHub repo, automatically
  • Wayback Machine — snapshots the rendered site; Zenodo keeps files, not web pages
  • your library — institutional repositories add an institutional commitment
  • Zenodo: launched 8 May 2013, successor of OpenAIRE's "Orphan Records Repository", run by CERN on Invenio
  • deposits sit in the CERN Data Centre next to LHC data; retention = lifetime of the lab; 50 GB per record, free
  • Software Heritage: Inria, announced 30 June 2016, UNESCO since 2017 — mission: all public source code, 20+ billion files; their repos are probably already in it
  • Wayback Machine: since 1996 — keeps the rendered site; Zenodo keeps files, not pages

The GitHub → Zenodo flow

  • authorize once, flip the toggle, make a release (tag = version); Zenodo picks it up in minutes; red deposit = usually a JSON error
  • a DOI is a name, not an address: Handle System, DOI Foundation ~2000, DataCite 2009 — links rot because identity is coupled to location; the DOI decouples them
  • semver, ~2010 — for editions: MAJOR = text/structure changed, MINOR = content added, PATCH = corrections
  • versions turn "it changed since I cited it" from scandal into citation practice

The GitHub → Zenodo flow

  • Zenodo's own onboarding says it in three steps too — the page they'll see after linking GitHub

Declare yourself


{
  "title": "My Digital Edition",
  "creators": [
    { "name": "Last, First",
      "orcid": "0000-0000-0000-0000" }
  ],
  "license": "cc-by-4.0"
}

.zenodo.json — what Zenodo reads at deposit time. Without it, Zenodo guesses 


cff-version: 1.2.0
message: "If you use this edition, cite it."
title: "My Digital Edition"
authors:
  - family-names: Last
    given-names: First
license: CC-BY-4.0

CITATION.cff — what GitHub reads: adds a “Cite this repository” button (citation-file-format.github.io)

the license — the choice you just made, written where machines can read it: the deposit displays it, and reuse is unambiguous

your identity — an ORCID is a persistent identifier for you: it survives name changes and moves, and ties the edition to its editor

  • Zenodo is named after Zenodotus of Ephesus, first head librarian of Alexandria (3rd c. BC) — first systematic metadata: alphabetical order, tags on scrolls. .zenodo.json = the tag on the scroll, 2,300 years later
  • both files in the repo root, dot included; "contributors" need a "type" field — the classic red-deposit failure
  • CITATION.cff adds GitHub's "Cite this repository" button; both can coexist
  • ORCID (2012) = a DOI for people: survives name changes, moves, and all the scholars named Wang Wei — two minutes, free

Wear the badge


[![DOI](https://img.shields.io/badge/DOI-<doi>-blue)](https://doi.org/<doi>)

One line in the README: the edition announces its own citable, archived self.

shields.io renders badges for anything — DOI, license, release — as simple, reliable images

  • shields.io badge is static: the DOI never changes, nothing needs to be live
  • backstory if asked: GitHub proxies README images (camo), Zenodo's badge server is rate-limited, camo caches the failure → broken icon
  • the slash in the DOI must be %2F

Aside: anonymous, for now

Sometimes the repo must not name you — yet.

  • double-blind review — the journal wants the edition, without the editor
  • Anonymous GitHub — an anonymized mirror of your repo: names, links and paths scrubbed, one shareable URL, with an expiration date
  • after acceptance — de-anonymize, release, deposit: the DOI takes over the identity work
  • anonymous.4open.science: anonymized mirror for double-blind review — names, links, paths scrubbed, one URL, expiration date
  • identity is managed: claim it forever (DOI, ORCID) or withhold it for a while (mirror)

05

Hands-on: archive your edition

  • this morning you made an edition; in twenty minutes it will be citable — sandbox accounts ready

This morning you made an edition. Now make it citable.

  1. Sign up at sandbox.zenodo.org (via GitHub)
  2. Flip the switch on your edition repo
  3. Add a .zenodo.json to the repo root
  4. Create a release (tag = version number)
  5. Admire your DOI — and grab the badge
  • sandbox = playground, real Zenodo later at home
  • most common failure: JSON syntax error → red deposit → fix, new release
  • short on time: 5-min live demo, students replicate later
